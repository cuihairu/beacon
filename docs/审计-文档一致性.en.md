# Documentation and source code consistency audit

> 2026-10-08 executed per the *Documentation and source code consistency audit specification*: every documentation surface is checked against the source code as ground truth,
> with `file:line` evidence given for each of the three kinds of discrepancy (① docs ahead of code / ② code ahead of docs / ③ description mismatch).
> Fixes touch documentation only — never code in reverse (changing code to match docs is forbidden). Any newly added feature must write back to the corresponding row of this document.

## 1. Audit scope and method

The documentation surface totals 14 documents: `README.md`, `docs/{index,mission,mission-excerpt,mvp-issues,positioning,solution-structure,troubleshooting,configuration,master-plan,acceptance-checklist}.md`, `docs/acceptance-{B705-L0-behavior,B803-e2e-walkthrough}.md`, `docs/rfc/RFC-001-technical-design.md`, plus a cross-check of `mkdocs.yml` navigation. (Starting with the 2026-10-11 incremental re-review, `configuration.md`, `master-plan.md` and `acceptance-checklist.md` came into scope; at the time of the F-01~34 baseline audit they did not yet exist or were not included.)

Method: draw verifiable technical claims and take evidence against the code one by one (component type strings, interface signatures, config keys, file names, package references, window forms, refresh cycles); before concluding from an empty grep result, first verify that the path exists (e.g. `ls src/`), then judge 「does not exist」. `mission-excerpt.md` (the original proposal archive) and the two acceptance documents (dated acceptance records) are treated as historical literature; only their still-live code references are checked.
