
# Documentation and source code consistency audit

> Executed on 2026-10-08 per the "Documentation and source code consistency audit specification": all documentation surfaces checked against source code as the source of truth,
> with the three difference categories (① document ahead of code / ② code ahead of document / ③ description mismatch) each backed by `file:line` evidence.
> Fixes only modify documents, never code (reverse code changes forbidden). Newly added features must be written back to the corresponding rows of this document.

## 1. Audit scope and method

14 documentation surfaces in total: `README.md`, `docs/{index,mission,mission-excerpt,mvp-issues,positioning,solution-structure,troubleshooting,configuration,master-plan,acceptance-checklist}.md`, `docs/acceptance-{B705-L0-behavior,B803-e2e-walkthrough}.md`, `docs/rfc/RFC-001-technical-design.md`, plus the `mkdocs.yml` navigation. (From the 2026-10-11 incremental review onward, `configuration.md`, `master-plan.md`, and `acceptance-checklist.md` were brought into scope; at the F-01~34 baseline audit they did not yet exist or were not included.)

Method: sample verifiable technical claims and gather evidence against the code one by one (widget type strings, interface signatures, configuration keys, file names, package references, window forms, refresh periods); a null grep result first requires verifying the path exists (e.g. `ls src/`) before concluding "does not exist". `mission-excerpt.md` (original plan archive) and the two acceptance documents (dated acceptance records) are treated as historical literature; only the code references that are still alive are checked.
