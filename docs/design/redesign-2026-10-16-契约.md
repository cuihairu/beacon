## 1. 四类概念（State / Event / Command / Operation Result）

| 概念 | 仓内落点 | 语义 |
|---|---|---|
| **State** | `WidgetState`（12 字段定性见映射与迁移 §2.1）+ `IStateStore`（快照面） | 外部系统事实的标准化投影 + 派生态（IsStale/ConnectionHealthy）；唯一权威快照在 State Store |
| **Event** | `Events/Events.cs` 六记录：`WidgetStateChanged` `ConnectionHealthChanged` `WidgetsInvalidated` `AggregateStatusChanged` `NotificationRaised` `ActionExecuted` | 状态流传输面；订阅与取消订阅沿 `IEventBus.Subscribe/Publish`（UI 侧经 `SubscribeOnUi` marshal 回 UI 线程，RFC §11） |
| **Command** | `ActionConfig.Type`（7 个 Type 字符串）→ `ActionRunner` → `IActionExecutor` | 用户意图的单一入口；执行后定向刷新走 `RefreshScheduler.Kick`（Action 后状态回灌），不另设命令总线 |
| **Operation Result** | `ActionResult(ActionId, Success, Message, OutputPath, CompletedAt)`（`Models/ActionModels.cs:28`） | 现行两态（bool Success）；目标五态见 §4 已代决③ |

## 2. 状态流契约（冻结）

1. **发布点**：`WidgetHost` 成功路径与陈旧路径统一经 `IStateStore.Update` 发布（`f5d1d91` 起）；`WidgetStateChanged` 事件形状不变，UI 无感。
2. **IStateStore 签名**（`Abstractions/IStateStore.cs`，`f5d1d91` 落地即冻结）：`Update(WidgetState)` / `Get(widgetId)` / `Snapshot()` / `Invalidate(widgetIds)`。
3. **变更检测口径**（`Services/StateStore.cs` 内容键）：除 `FetchedAt` 外全字段参与（长度前缀段防分隔符歧义；Payload 按键排序、插入顺序无关）；`IsStale` / `ConnectionHealthy` 翻转必发布（场景 F5：断网降级事件不得被去重吞掉，`StateStoreTests.DedupOn_StaleFlip_Republishes` 锚定）。
4. **去重默认启用**（`d71bdc8`，已代决②）：仅刷新时间变化不触发下游；快照仍保最新 `FetchedAt`。
5. **失效**：`WidgetsInvalidated` 消费方负责丢弃本地残留；`Invalidate` 为 Store 侧对应清理面（App 侧共享 Store 接线归 Phase 3 绑定引擎一并做，现状 UI 走事件总线不受影响）。

## 3. 组件契约（冻结，兼容方案四条照映射与迁移 §5 采纳）

1. 六个 JSON 文件名与既有字段语义不变（config / connections / widgets / pins / actions / notifications）。
2. 新组件模型以 `WidgetConfig` 增量可选字段进入，旧文件可读；不迁移、不重命名。`ConfigVersion` 仅在需要
   迁移语义时递增——纯增量可选字段不落键故不动（⑤⑧⑨ 均有单测锚定），存量配置零噪声。
3. 既有 23 个 Widget 类型键、7 个 Action Type 字符串、全部窗口层级（L0-L3 + Settings）保留；组件化只替换渲染段与状态入口。
4. 装机 71 条清单与 CI 视觉取证场景继续有效，Phase 6 全量回归后才算期次完成。
5. 组件描述符形状与挂载面（已代决⑤，`src/Beacon.Core/Models/ComponentDescriptor.cs`）：
   `ComponentDescriptor(Id, Type, Props, Children)` → `WidgetConfig.Components: Dictionary<string, ComponentDescriptor>?`
   （面键开集，现行词汇 tile / row / detail）；嵌套组合允许且带上限（8 层 / 32 子 / 256 节点）；
   结构非法 = 整树弃用回传统渲染 + 诊断，不静默裁剪。
6. 绑定与实例（已代决⑥，`src/Beacon.Core/Models/ComponentBinding.cs` + `Services/WidgetInstanceResolver.cs`）：
   绑定随节点进树（`ComponentBinding(Field, Source)`），源三态 state / selector / const；
   实例 = 面键解析结果，fail-closed（无面树/非法树 → null → 传统渲染）；实例与配置只读共享、解析无 IO。
7. 绑定引擎（已代决⑦，`src/Beacon.Core/Services/ComponentBindingEngine.cs`）：树内每个绑定节点的 Field 值按
   `{节点路径}.{字段}` 键出（路径与校验诊断同口径）；源名映射保留键 `""` = 自身状态；
   一切取不到值的绑定回空串（fail-closed），不抛、不猜；选择器源只接 Core 既有纯函数选择器。
8. 数据源聚合（已代决⑧，`WidgetConfig.Sources: Dictionary<string, Dictionary<string,string>>?`
   面键 → 源名 → widgetId）：源名大小写敏感精确匹配、不得使用保留键 `""`（实例自身状态）、
   每面 ≤16 源；声明非法整面弃用（附加源全丢，自身状态恒可用）+ 诊断进加载日志；
   运行时源映射由 `WidgetInstanceResolver.ResolveSources` 从状态快照按 widgetId 查取构建，
   查不到的源缺席（绑定侧回空串）；组合在组件层聚合多个 WidgetId，`WidgetState` 单
   `ConnectionId` 的 Provider 口径不动。
9. 共享消费（已代决⑨，`src/Beacon.Core/Services/ComponentSourceIndex.cs`）：同一份状态对象可供任意多个
   实例消费（解析纯函数、按引用共享不复制）；`ConsumedWidgetIds(instance)` 给出实例所需 widgetId 全集
   （自身 Id 在前、附加源按声明顺序、同 widgetId 去重），`SourcesOf(instances)` 反查 widgetId → 消费
   实例集合；索引按需重建、不落缓存。
10. 组件层纯函数边界（已代决⑩）：`ComponentTreeValidator` / `ComponentSourcesValidator` /
    `WidgetInstanceResolver` / `ComponentBindingEngine` / `ComponentSourceIndex` 全为静态类（无实例状态、
    无缓存面），任何公共方法都不接收运行时服务（Provider / 执行器 / Store / 事件总线 / Clock 等）——
    状态与配置只作为数据参数传入；状态查取次数只由源声明决定、与布局形状无关，引擎解析期零查取。
    改布局 = 对同一份状态快照重新解析，不产生数据请求（Phase 3 行 6 的构造与测试双锚定）。
