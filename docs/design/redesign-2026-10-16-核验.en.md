> **Nature statement**: the design draft under verification is an **external suggestion, not a fact of this repository**. The 「已有实现 / 此前设计」 (existing implementations / prior designs) it mentions are all treated as **undocumented** until verified; this table is the verification record made before any work starts.

> **The meaning of "Not found"**: it only means the thing was **never written down** in this repository's code or documentation; it **cannot prove it was never designed**. ## 1. Verification conventions

| Classification | Meaning | Notation |
|---|---|---|
| **Implemented** | The code exists and in-repo documentation already records it | Give `file:line` + documentation source |
| **Partially implemented** | The claim can be split and is labeled item by item | Implemented parts get `file:line`; non-implemented parts are written as "Not found" |
| **Exists but undocumented** | The code exists but in-repo documentation never recorded it (including cases where docs state only acceptance criteria, not the mechanism) | Give `file:line` and mark it as needing backfill |
| **Not found** | Neither code nor documentation has it | Write "Not found"; if the repo has counter-records or deferral records, attach the source and the design draft's original text |

Items that are "implemented in part" are always written out item by item; vague conclusions like 「大致符合」 ("roughly matches") are not used.
