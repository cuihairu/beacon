
# Beacon Componentization Refactor · State Flow and Component Contract Freeze (Phase 0 closing delivery)

**Basis**: `docs/design/redesign-plan-2026-10-16.md` (external design draft) + `docs/design/redesign-2026-10-16-核验.md` (50-item current-state verification, `759742b`) + `docs/design/redesign-2026-10-16-映射与迁移.md` (§6 pending-decision list, `e1229fc`).
**Time point**: 2026-10-16. The PATROL1016 inspection ticket authorized 「可自主决策的直接拍板并写进仓内决策记录」 — this file is that decision record; irreversible or out-of-scope matters remain open questions (see §4).

## 1. Four concepts (State / Event / Command / Operation Result)

| Concept | In-repo location | Semantics |
|---|---|---|
| **State** | `WidgetState` (12-field characterization in Mapping & Migration §2.1) + `IStateStore` (snapshot surface) | Normalized projection of external-system facts + derived state (IsStale/ConnectionHealthy); the single authoritative snapshot lives in the State Store |
| **Event** | `Events/Events.cs` six records: `WidgetStateChanged` `ConnectionHealthChanged` `WidgetsInvalidated` `AggregateStatusChanged` `NotificationRaised` `ActionExecuted` | The state stream's transport surface; subscribe and unsubscribe via `IEventBus.Subscribe/Publish` (the UI side marshals back to the UI thread via `SubscribeOnUi`, RFC §11) |
| **Command** | `ActionConfig.Type` (7 Type strings) → `ActionRunner` → `IActionExecutor` | The single entry point for user intent; the targeted refresh after execution goes through `RefreshScheduler.Kick` (state flows back after an Action); no separate command bus is introduced |
| **Operation Result** | `ActionResult(ActionId, Success, Message, OutputPath, CompletedAt)` (`Models/ActionModels.cs:28`) | Current two states (bool Success); the target five states are in §4 已代决③ |

## 2. State flow contract (frozen)

1. **Publish point**: the success path and the stale path of `WidgetHost` both publish uniformly via `IStateStore.Update` (since `f5d1d91`); the `WidgetStateChanged` event shape is unchanged and the UI notices nothing.
2. **IStateStore signature** (`Abstractions/IStateStore.cs`, frozen as landed in `f5d1d91`): `Update(WidgetState)` / `Get(widgetId)` / `Snapshot()` / `Invalidate(widgetIds)`.
3. **Change detection rule** (`Services/StateStore.cs` content key): all fields except `FetchedAt` participate (length-prefixed segments guard against delimiter ambiguity; Payload is sorted by key, insertion-order independent); an `IsStale` / `ConnectionHealthy` flip always publishes (scenario F5: the offline-degradation event must not be swallowed by dedup, anchored by `StateStoreTests.DedupOn_StaleFlip_Republishes`).
4. **Dedup enabled by default** (`d71bdc8`, 已代决②): a refresh-time-only change does not trigger downstream; the snapshot still keeps the latest `FetchedAt`.
5. **Invalidation**: consumers of `WidgetsInvalidated` are responsible for dropping local residue; `Invalidate` is the matching Store-side cleanup surface (App-side wiring of the shared Store is handled together with the Phase 3 binding engine; the current UI goes through the event bus and is unaffected).

## 3. Component contract (frozen; the four compatibility items adopted as in Mapping & Migration §5)

1. The six JSON file names and existing field semantics are unchanged (config / connections / widgets / pins / actions / notifications).
2. The new component model enters as incremental optional fields on `WidgetConfig`; old files stay readable; no migration, no renaming. `ConfigVersion` only increments when migration semantics are actually needed —
   pure additive optional fields write no keys, so it stays untouched (⑤⑧⑨ each have unit test anchors); zero noise for existing config.
3. The existing 23 widget type keys, 7 Action Type strings, and all window layers (L0-L3 + Settings) are preserved; componentization only replaces the rendering segment and the state entry point.
4. The 71-item on-machine acceptance checklist and the CI visual-evidence scenarios remain in force; the phase counts as complete only after the full Phase 6 regression.
5. Component descriptor shape and mounting surface (已代决⑤, `src/Beacon.Core/Models/ComponentDescriptor.cs`):
   `ComponentDescriptor(Id, Type, Props, Children)` → `WidgetConfig.Components: Dictionary<string, ComponentDescriptor>?`
   (open set of surface keys, current vocabulary tile / row / detail); nested composition is allowed with blast-proof caps (8 levels / 32 children / 256 nodes);
   structurally invalid = discard the whole tree back to traditional rendering + diagnostics, no silent pruning.
6. Bindings and instances (已代决⑥, `src/Beacon.Core/Models/ComponentBinding.cs` + `Services/WidgetInstanceResolver.cs`):
   bindings enter the tree with their node (`ComponentBinding(Field, Source)`); sources have three kinds: state / selector / const;
   an instance = the surface-key resolution result, fail-closed (no surface tree / invalid tree → null → traditional rendering); instances and config are shared read-only, resolution does no IO.
7. Binding engine (已代决⑦, `src/Beacon.Core/Services/ComponentBindingEngine.cs`): every bound node in the tree keys its Field value out as
   `{node path}.{field}` (same convention as the validation diagnostics); the source-name map reserves key `""` = own state;
   any binding that cannot resolve a value returns an empty string (fail-closed) — no throwing, no guessing; selector sources hook up only Core's existing pure-function selectors.
8. Data source aggregation (已代决⑧, `WidgetConfig.Sources: Dictionary<string, Dictionary<string,string>>?`
   surface key → source name → widgetId): source names match exactly and case-sensitively; the reserved key `""` (the instance's own state)
   must not be used; ≤16 sources per surface; an illegal declaration discards the whole surface (all extra sources dropped, own state always available) + diagnostics into the load log;
   the runtime source map is built by `WidgetInstanceResolver.ResolveSources` from the state snapshot via widgetId lookup,
   sources that cannot be found are simply absent (the binding side returns an empty string); composition aggregates multiple WidgetIds at the
   component layer, and the `WidgetState` single-`ConnectionId` Provider convention is untouched.
9. Shared consumption (已代决⑨, `src/Beacon.Core/Services/ComponentSourceIndex.cs`): one and the same state object can be consumed by
   any number of instances (resolution is a pure function, shared by reference, not copied); `ConsumedWidgetIds(instance)` gives the full set of widgetIds
   an instance needs (own Id first, extra sources in declaration order, duplicate widgetIds deduped), and `SourcesOf(instances)` reverse-maps widgetId → consuming
   instance set; the index is rebuilt on demand and never cached.
10. Component-layer pure-function boundary (已代决⑩): `ComponentTreeValidator` / `ComponentSourcesValidator` /
    `WidgetInstanceResolver` / `ComponentBindingEngine` / `ComponentSourceIndex` are all static classes (no instance state,
    no cache surface); no public method takes runtime services (Provider / executors / Store / event bus / Clock, etc.) —
    state and config enter only as data parameters; the number of state lookups is decided solely by the source declarations and is independent of layout shape, and the engine does zero lookups during resolution.
    Changing layout = re-resolving against the same state snapshot, producing no data requests (doubly anchored by the construction and tests of Phase 3 row 6).

## 6. Capability boundary, three tiers (P0-01, 2026-10-17)

The component contract says 「what can be written」; actual support is labeled in three tiers, per surface (`tile` / `row` / `detail`)
below — do not mistake 「the contract allows it」 for 「it is accepted」; acceptance follows the on-machine checklist (§3.4's 71 items + the Phase 6 full regression):

| Tier | Scope | tile | row | detail |
|---|---|---|---|---|
| Core model available | `ComponentDescriptor` / tree validation / source validation / `WidgetInstanceResolver` / `ComponentBindingEngine` / `ComponentSourceIndex` (static pure functions, anchored by Core unit tests) | ✅ | ✅ | ✅ |
| App wired | Declarative rendering + binding reads + extra-source routing (PinTile / FloatingTile / QuickPanel rows / DetailWindow) + missing-source display | ✅ | ✅ | ✅ |
| Real user scenario accepted | 71-item on-machine checklist + Phase 6 regression + sample runtime acceptance (`docs/samples/declarative-vertical-sample.md` "What to verify") | ⏳ | ⏳ | ⏳ |

Convention note: saving a component tree only persists to disk + re-registers (P3-02 split), fetching no data and
publishing no re-render event — a surface renders with the new tree on the **next state arrival**; when no content
change is suppressed by dedup, reopening the surface shows it. The settings-page save copy no longer claims 「正在重渲染」.
