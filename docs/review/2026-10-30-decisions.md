# Beacon 阻塞项决策建议

分析日期：2026-10-30。范围：当前工作区 `todo.md` 全文；未发现 `TODO.md`。共纳入 **17 条 BLOCKED + 1 条等待真机确认的未完成项**，下文逐项对应，没有把重复主题合并后漏掉原条目。条目标识采用当前文件行号。

本文是建议单，不代表用户已经采纳，也不代表测试已经执行。文中的“立即执行动作”是下一次执行任务可直接照做的步骤；本次仅只读检查仓库，并写本文件，没有安装、登录、调用真实服务、修改配置或执行远端动作。

## 先理解该怎么决策

目前最值得投入的是补齐真实使用证据，而非继续添加功能。自动化测试像在台架上检查汽车发动机，真实桌面验收像上路：两者都必要，前者通过不能证明后者通过。

建议分四组推进：

| 顺序 | 工作包 | 对应下文 | 需要的资源 | 完成标准 |
|---|---|---|---|---|
| 1 | 点击穿透与可操作性先验 | 05、07 | 解锁的 Windows 桌面 | 明确是否存在穿透与点击、拖动冲突，决定后续测试路径 |
| 2 | 一次普通桌面验收 | 02、03、04、07、08、09、10、13、15、16、18 | 同一 Windows 构建、录屏、默认浏览器；真实动作另需测试仓库 | 每条有独立证据与通过/失败记录 |
| 3 | 多屏专项 + 长时驻留 | 01、06、14、17 | 不同缩放的双屏、日常使用时段 | 拖动/拓扑变化/恢复记录，以及长时运行记录 |
| 4 | 干净环境复跑 | 11 | 干净 Windows 11 虚拟机 | 下载到完整主链走通，排除开发环境依赖 |
| 延后 | 私有厂商适配 | 12 | 目标、文档、授权测试条件 | 输入齐备后再排期 |

以上可复用同一次录屏、同一组截图和日志，但每条必须单独判定。建议普通桌面专项预留约半天，多屏约 1 小时，干净 VM 约半天，稳定性覆盖一个工作日；这是安排时间的预算，不是实测工时或仓库既定门槛。发现缺陷后的修复时间另计。

所有验收建议固定构建版本/提交号与 SHA256，记录 Windows 版本、屏幕缩放、操作时间、预期、实际、证据位置。否则很容易拿旧版本截图证明新版本。后续证据可由执行者保存到仓库外验收目录；本次不按旧清单要求向 `docs/` 写入任何东西。

## 01｜跨 DPI 拖动：补真实双屏证据

> 执行状态（2026-10-30，exec-actions 批）：待用户：不同缩放双屏 Windows 会话；执行清单见 docs/review/2026-10-27-manual-acceptance-supplement.md A-1。

来源：`todo.md:45`。DPI 可理解为系统的显示缩放，例如同样大小的文字在 100% 与 150% 屏幕上的换算。

**推荐决策：保留未验状态，合并到一次不同缩放双屏专项，不重做普通拖动测试。**

理由：

- **成本**：现有 R/R3 已覆盖普通拖动与恢复；重复跑这些用例很便宜，但不能消除跨屏的不确定性。
- **收益**：借用已有双屏并设置不同缩放，一次就能观察尺寸跳变、拖动闪烁、坐标偏移这些真实问题。
- **风险**：两块屏幕都用相同缩放仍可能漏问题；数学单测通过也不等于鼠标拖动过程正确。

**立即执行动作**：在双屏 Windows 上记录分辨率及缩放（建议 100%/150%），先做第 05 项可操作性检查，再将同一 tile 来回拖动三轮，分别记录落点、字体、进度条、重启还原情况；与第 06、17 项共用会话。

**明确不做/延后**：不为这一个验收项采购设备；不拿单屏改缩放或相同缩放双屏冒充完整验收。资源未就绪时明确保留未验。

## 02｜打开 URL：用真实默认浏览器验最终结果

> 执行状态（2026-10-30，exec-actions 批）：待用户：解锁 Windows 与默认浏览器会话；清单 A-2。

来源：`todo.md:58`。

**推荐决策：维持现有 URL 模板实现，补一次 Windows 默认浏览器端到端检查。**

理由：

- **成本**：拼接单测已存在；额外工作主要是几次真实点击与截图。
- **收益**：能发现“字符串正确，但系统打不开、打开错对象、重复打开”的集成问题。
- **风险**：浏览器已登录或历史页面可能掩盖问题，必须核对最终地址与目标对象，不能只看浏览器出现。

**立即执行动作**：使用无凭据的测试链接，选择普通地址、带空格/中文等需转义的参数、缺失必填值三种情况；从 Beacon 正常入口打开，记录最终地址、页面对象和应用反馈。缺失值按现有产品约定判定是否拒绝或明确报错。

**明确不做/延后**：不扩展为全浏览器兼容性工程；本轮只验用户当前默认浏览器。不把第 15 项“不打开浏览器完成 Retry”的主链混为本项。

## 03｜Toast 通知：验“看到、点击、到对地方”

> 执行状态（2026-10-30，exec-actions 批）：待用户：解锁 Windows 通知会话（含勿扰/权限状态记录）；清单 A-3。

来源：`todo.md:63`。Toast 指 Windows 通知横幅及通知中心里的消息。

**推荐决策：将通知发送、可见呈现和点击路由作为三个独立检查点。**

理由：

- **成本**：已有 AUMID 注册自愈证据，无需再围绕快捷方式或注册表反复开发。
- **收益**：三段分开记录，能区分应用没发、系统没展示、点击后没到正确详情三种问题。
- **风险**：日志显示已发送不代表用户看到了；勿扰模式或通知权限也会影响表现，需先记录系统设置。

**立即执行动作**：在解锁的 Windows 上记录通知权限与勿扰状态，制造一条可控失败，拍下横幅和通知中心记录；点击通知，检查对应组件/详情。再从通知中心里的同一条消息验证入口，并记录是否重复执行动作。

**明确不做/延后**：不以 JSON 通知记录或 AUMID 注册键替代点击证据；本轮不改通知框架，也不追求所有系统通知设置组合全覆盖。

## 04｜托盘状态刷新：验真实通知区

> 执行状态（2026-10-30，exec-actions 批）：待用户：Windows 通知区可见会话；清单 A-4。

来源：`todo.md:66`。

**推荐决策：在固定刷新配置下，验证托盘状态与当前状态在约定刷新窗口内一致。**

理由：

- **成本**：把托盘图标移到可见通知区即可取证，不需要新建测试平台。
- **收益**：补上 tile 已变化、托盘却未更新的盲区；用户实际靠托盘判断是否需要关注。
- **风险**：托盘可能显示汇总严重程度，不能简单要求它总与某一个 tile 同色；隐藏图标或旧截图也会误判。

**立即执行动作**：只保留可控测试组件或明确记录全部组件状态，展开通知区；依次产生健康、失败、恢复状态，记录配置的刷新周期、状态变化时间与托盘截图。先按现有汇总规则写出期望颜色再判断。

**明确不做/延后**：不新增轮询机制、不缩短默认周期来掩盖刷新问题；颜色自定义另见第 08 项。

## 05｜点击穿透：先核验现有裁定是否损害交互

> 执行状态（2026-10-30，exec-actions 批）：待用户：解锁 Windows 交互冒烟（记事本覆盖/下钻/拖动/前台输入四查）；清单 A-5。仓库事实复核（2026-10-30）：FloatingTileWindow.cs:403 现确有 WS_EX_TRANSPARENT（常量在 Infrastructure/NativeMethods.cs:31），B-701 注释明示整窗穿透、选择性命中测试有意延后——本节「静态设置存在」判断与仓库一致；todo:30 的 2026-10-19 winverify 记录（「无 WS_EX_TRANSPARENT」）系 B-701 批次加入前的旧况，历史行不追溯重写。

来源：`todo.md:71`，另见历史说明 `todo.md:25、30`。

**推荐决策：先做现实现的交互冒烟验收；若整窗穿透导致 tile 无法点击或拖动，建议下一步采用“默认可交互、显式选择穿透模式”的产品方案，待采纳后实现。** 不在本报告中推翻已有用户裁定，也不直接改代码。

理由：

- **成本**：先花几分钟在记事本上方测试，比直接投入选择性穿透或鼠标钩子便宜得多。
- **收益**：先回答“用户还能否控制浮窗”，可避免后续多屏、拖动、下钻验收走到一半才发现前提不成立。
- **风险**：当前 `FloatingTileWindow.cs:403` 确有 `WS_EX_TRANSPARENT`，代码注释明确为整窗穿透；这与早期“代码中没有该设置”的记录不同。但静态设置存在不能证明跨进程穿透已经成功。
- **取舍**：被动查看与点击下钻/拖动是两种需求。显式模式能让用户理解行为；整窗永久穿透若阻断交互，则与 RFC §6.2.7 的点击下钻要求发生冲突。

**立即执行动作**：让 tile 覆盖另一个进程的记事本，依次测试点击是否到达下层、tile 点击是否仍能下钻、拖动是否可用、前台输入是否受影响；用同一版本录屏。若冲突，记录产品问题并形成模式选择方案，先验证现有托盘/设置入口是否足以恢复控制，再安排实现。

**明确不做/延后**：继续遵守“不使用全局鼠标钩子”的既有裁定；不声称整窗穿透和完整鼠标交互已同时验证；不把宿主面板的命中测试行为直接当作浮窗行为。精细到空白区域的选择性穿透延后。

## 06｜跨屏与降分辨率后的越界回收

> 执行状态（2026-10-30，exec-actions 批）：待用户：双屏+改分辨率/热插拔会话；清单 A-6。

来源：`todo.md:77`。

**推荐决策：与第 01 项同场执行，但单列越界回收结论。优先真实双屏，虚拟显示仅作补充。**

理由：

- **成本**：复用双屏会话，追加修改分辨率和断开显示器的操作即可。
- **收益**：保证 tile 不会“跑到不存在的屏幕上”，避免用户误以为软件丢失或失灵。
- **风险**：虚拟屏能改变拓扑，却未必复现真实热插拔时序；普通拖动通过不能替代这一检查。

**立即执行动作**：把 tile 放到副屏右下角，降低副屏分辨率，检查是否回到可见区域；再断开/重连副屏并重启，记录 tile 是否仍可找回、是否出现重复窗，保留前后屏幕拓扑与位置配置副本。

**明确不做/延后**：不为验收先安装不熟悉的虚拟显示驱动；未取得真实热插拔证据的部分继续保留未验。

## 07｜RFC 四条铁律：按用户体验逐条验

> 执行状态（2026-10-30，exec-actions 批）：待用户：解锁 Windows 输入/焦点场景；清单 A-7。

来源：`todo.md:80`；依据：`docs/rfc/RFC-001-technical-design.md:278`、`docs/zh/acceptance-B705-L0-behavior.md`。

**推荐决策：将“不打断工作”作为核心验收门槛，与通知测试共用场景，但独立判定。**

理由：

- **成本**：四条规则已经写清楚，无需重新设计产品，只需在输入、失败、断网场景中观察。
- **收益**：验证显示状态、点击下钻、不承载需确认动作、不抢焦点及不进任务栏/Alt-Tab，直接对应桌面常驻产品的信任感。
- **风险**：通知引擎按规则发 Toast 与 L0 自己弹窗是不同来源；把所有通知都禁掉会掩盖通知功能问题。
- **收益**：同时做“有意点击能进入详情”和“未操作时不打断输入”，可避免只证明静止时安静。

**立即执行动作**：在记事本持续输入期间制造 Critical 和断网/恢复，记录焦点、声音、弹窗、Alt-Tab/任务栏；随后验证点击下钻及动作入口。按四条分别填写结果，第 05 项交互冲突如出现，必须记失败或待决，不能整包标绿。

**明确不做/延后**：不因静态代码审计通过就勾选；不通过关闭全部通知来证明“不打扰”；不临时扩充成任意网络环境兼容性测试。

## 09｜动效观感：保留 reduced 默认，允许关闭

> 执行状态（2026-10-30，exec-actions 批）：待用户：真人工作片段观察（off/reduced/full 三档对比）；清单 A-9。

来源：`todo.md:85`。

**推荐决策：保持现有 reduced 默认及 off 选项，先验证舒适度，不凭个人偏好增强调节范围。**

理由：

- **成本**：已有档位、持久化和帧差分证据，短时间日常任务观察就能补主观体验。
- **收益**：默认克制、可关闭，照顾需要提示和容易受干扰的两类用户。
- **风险**：动画“确实在动”不等于“不干扰”；长时呼吸或 Critical 脉冲可能在真实工作时分散注意力。

**立即执行动作**：在实际阅读/输入任务中比较 off、reduced、full，至少观察一个工作片段并记录“是否分心、Critical 是否可察觉、能否方便关闭”；优先用 reduced，强度先保持现值。记录观察者偏好与客观故障，二者分开。

**明确不做/延后**：不把单人试用外推为所有人的舒适度结论；不新增动画家族、不默认开启 full，也不因帧差分通过就宣布观感通过。
