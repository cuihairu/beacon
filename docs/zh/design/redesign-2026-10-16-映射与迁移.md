## 2. 状态模型字段定性（业务状态 / 显示字段 / 本地偏好 / 元数据）

### 2.1 `WidgetState`（`src/Beacon.Core/Models/WidgetState.cs:4-21`）

| 字段 | 定性 | 说明 |
|---|---|---|
| `WidgetId` `WidgetType` `ConnectionId` | 标识 | 稳定键，非状态 |
| `Severity` `Lifecycle` | **业务状态** | 外部系统事实的标准化投影 |
| `Progress` | **业务状态** | 0..1 归一化进度 |
| `Payload` | **业务数据** | 供 Action 模板变量（run_id 等） |

| 类别 | 字段 |

## 4. 差异与迁移计划（按期）

### Phase 1 响应式状态与数据流

1. 引入 `IStateStore`（进程内实现）：快照读取 + 订阅 + 内容级变更检测。`WidgetHost` 刷新成功后改写入 Store，Store 判变后发 `WidgetStateChanged`——**发布点从 WidgetHost 移到 Store**，事件契约不变，UI 无感。
2. 变更检测口径：`WidgetState` 内容相等移除 `FetchedAt`（或加 `ContentVersion`），使「仅刷新时间变化」不再触发下游。
3. Selector 收编：`QuotaWindows` / `WidgetValueHint` / `QuickPanelSections` / `QuickPanelFilter` 归位为 Selector 层，签名不动，只挪命名空间与文档定位。
4. **回归面**：去重后 UI 不再每 tick 重建——场景 S（事件流）、O（面板计数）、Q（胶囊计数）必须全绿；F5（断网降级恰 1 条通知）依赖 stale 事件不被去重吞掉，需单测先行。
5. 回退：Store 引入为旁路（一次 commit 可整体回退），不合并进 WidgetHost 改写。

### Phase 2 设计系统与基础组件库

1. 令牌化：`UiPalette` / `ThemeColors` / `MotionEngine` / `DpiLayoutMath` 收编为令牌层；**色值不得变**（G 系 CI 像素断言锚现有色值，改值即红）。
2. 第一批组件从 `MakeStateRow` 反推：Metric、Status Indicator、Progress、Key-Value、Status Card、List、Action Button、Link、Stack、Grid、Section、Conditional、Empty、Loading、Error、Offline。
3. 视觉示例页独立成窗（仅 debug 构建），不进产品窗口集。

### Phase 3 组件组合与数据绑定

1. `Component Descriptor`：在 `WidgetTypeDescriptor` 之上加显示声明（组件类型 + 绑定 + 密度），**不推翻既有 23 个类型键**。
2. `WidgetConfig` 增量可选字段（`ConfigVersion` 递增，旧文件可读）——兼容方案见 §5。
3. Selector 到组件属性绑定 + 多数据源组合（`WidgetState` 单 `ConnectionId` 的现状不破坏，组合发生在组件层聚合多个 WidgetId）。

### Phase 4 HTML 小屏幕

**前置拍板**：与 `docs/master-plan.md:769`「不引入 WebView 或其他 UI 框架来重复实现桌面外壳」的边界裁定——HTML 只进「数据显示小屏幕」不进「外壳」，还是整体维持原生。裁定前不开工。

### Phase 5 / 6

组件目录扩展与全量回归；装机清单 71 条（`docs/acceptance-checklist.md`）继续作为验收底座，Phase 6 逐条复跑。
